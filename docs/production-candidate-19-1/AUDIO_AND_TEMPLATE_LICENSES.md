# VidiaForge V19.1 — Audio + Template Licensing

Production candidate `19-1` audio + template licensing documentation. This
document explains, in plain language, **what audio + template assets the
application can use, where they come from, what licenses they carry, and
what the user must do to comply with each license.**

It is written for a non-technical stakeholder (a project owner, a legal
reviewer, a content producer) — not for a developer. Where a license has
NOT been verified, the document says so plainly. Where a feature is
BLOCKED in the repair sandbox, the document says so plainly.

**Verification date:** 2025-10-10 (the date this document was written).
Live API verification is BLOCKED in the repair sandbox because there is
no internet egress; the contract tests verify the parsing + validation
logic against recorded fixtures, and live verification will be done once
the deployment has internet egress.

**V19.1 v5 honest-labeling update.** This revision (v5) updates the v3
document to reflect two honest-labeling changes:

1. Three of the eight built-in SFX entries have been **renamed** because
   their previous titles implied field recordings. "Camera Shutter" →
   "Synthetic Shutter", "Crowd Cheer" → "Synthetic Crowd Bed",
   "Rain Ambience" → "Synthetic Rain Bed". All 8 SFX are honestly
   labeled as synthetic (they are generated by FFmpeg from
   public-domain noise sources). The other 5 keep their generic titles
   because a synthetic whoosh / click / pop / notification / impact is
   still legitimately that thing.

2. The 13 template thumbnail PNGs are now documented as **layout
   previews** — they are illustrative compositions generated from the
   template's actual slot + clip structure (gradient background + title
   text + slot rectangles + text-slot defaultValues rendered at their
   real timeline positions). They are NOT frames from real rendered
   exports. The UI labels them with
   `alt="${template.title} layout preview"` and a visible "Layout" badge
   on the templates panel so users understand they are not seeing a
   finished-video preview.

## 1. Audio providers

VidiaForge ships two genuine external music providers (Internet Archive +
Jamendo) plus a built-in SFX library. The active music provider is
selected via the `AUDIO_PROVIDER` environment variable. SFX are always
served from the built-in library regardless of `AUDIO_PROVIDER`.

### 1.1 Internet Archive — `AUDIO_PROVIDER=internet-archive`

- **Asset source.** The Internet Archive (https://archive.org). The
  Internet Archive is a 501(c)(3) non-profit digital library that hosts
  millions of audio items contributed by institutions + individuals.
- **API documentation URL.** https://archive.org/advancedsearch.php
  (search) + https://archive.org/metadata/{id} (item metadata).
- **License or usage terms.** Each Internet Archive item carries its
  own `licenseurl` metadata field. The provider ONLY returns items whose
  license permits commercial use in user-generated video:
  - **CC-BY** (any version — e.g. 3.0, 4.0) — attribution required,
    commercial use allowed, derivative works allowed.
  - **CC-BY-SA** (any version) — attribution required, commercial use
    allowed, derivative works allowed, **share-alike** (the resulting
    work must carry the same license).
  - **CC0** (public domain dedication) — no attribution required,
    commercial use allowed, derivative works allowed.
  - **Public Domain mark** — no attribution required, commercial use
    allowed, derivative works allowed.
  - Items with **CC-BY-NC** (non-commercial only), **CC-BY-ND** (no
    derivatives), no license, or an unknown license are SKIPPED. The
    user is never offered audio whose licensing would forbid monetized
    or derivative user-generated video.
- **Attribution requirements.** Varies per item. The provider sets
  `attributionRequired = true` for CC-BY and CC-BY-SA items and
  `attributionRequired = false` for CC0 and Public Domain items. When
  attribution is required, the `attributionLine` field is populated with
  a human-readable string of the form
  `"${title}" by ${creator} (${licenseType}; ${licenseUrl})` — suitable
  for pasting into a video description or end-card.
- **Restrictions.**
  - Commercial use: **allowed** (NC licenses are filtered out).
  - Derivative works: **allowed** (ND licenses are filtered out).
  - Share-alike (CC-BY-SA tracks): the resulting video must be released
    under the same CC-BY-SA license. The provider surfaces this in the
    `licenseType` field so the user can see it before using the track.
- **Preview/download permissions.** The preview URL is the Internet
  Archive's direct file URL
  (`https://archive.org/download/{identifier}/{filename}`). The Internet
  Archive allows streaming + download of public-domain + CC-licensed
  audio; no login is required.
- **Verification date.** 2025-10-10 (date this document was written).
- **Configuration requirements.** Set `AUDIO_PROVIDER=internet-archive`.
  No credentials needed (the Internet Archive API is public). Optional:
  - `IA_SEARCH_QUERY` — the base search query (default: `collection:audio`).
  - `IA_MAX_RESULTS` — max number of tracks to return (default: `20`).
- **v5 default.** `AUDIO_PROVIDER=internet-archive` is now set by
  default on the `vidiaforge-api` service in `render.yaml` so the
  deployed music catalog is non-empty without any credentials. The
  Internet Archive adapter only returns CC-BY / CC-BY-SA / CC0 / Public
  Domain items (NC + ND licenses are filtered out). To use Jamendo
  instead, set `AUDIO_PROVIDER=jamendo` + `JAMENDO_CLIENT_ID` in the
  Render dashboard.
- **Status.** **IMPLEMENTED** — the adapter is in
  `src/lib/audio/internet-archive-provider.ts`; contract tests pass
  (`tests/unit/audio-provider-contract.test.ts`, 61 tests covering
  license parsing, duration parsing, MP3 file selection, category
  classification, and fixture-based item parsing). **Live verification
  BLOCKED** in the repair sandbox (no internet egress). The contract
  tests verify the parsing + validation logic against recorded
  fixtures; live API verification will be done once the deployment has
  internet egress.

### 1.2 Jamendo — `AUDIO_PROVIDER=jamendo`

- **Asset source.** Jamendo (https://www.jamendo.com) — an independent
  artist music platform that hosts CC-licensed music from independent
  artists. Founded in 2005; tens of thousands of CC-licensed tracks.
- **API documentation URL.** https://developer.jamendo.com/v3.0.
- **License or usage terms.** Each Jamendo track has a `license_ccurl`
  field. The provider ONLY returns tracks with:
  - **CC-BY** (any version) — attribution required, commercial use
    allowed, derivative works allowed.
  - **CC-BY-SA** (any version) — attribution required, share-alike,
    commercial use allowed, derivative works allowed.
  - **CC0** / **Public Domain** — no attribution required.
  - Tracks with **CC-BY-NC** (non-commercial), no license, or unknown
    licenses are SKIPPED.
- **Attribution requirements.** Same as the Internet Archive:
  `attributionRequired = true` for CC-BY / CC-BY-SA, `false` for CC0 /
  Public Domain. When attribution is required, the `attributionLine`
  field is populated as
  `"${title}" by ${artist} (${licenseType}; ${licenseUrl}) — via Jamendo`.
- **Restrictions.**
  - Commercial use: **allowed** (NC licenses are filtered out).
  - Derivative works: **allowed** (ND licenses are filtered out).
  - **Jamendo "Pro" license is NOT configured by this integration.**
    Jamendo offers a separate paid "Pro" subscription for commercial
    uses that exceed the CC terms (for example, using a CC-BY-NC track
    commercially, or removing the share-alike obligation from a
    CC-BY-SA track). Pro licensing requires a paid subscription to
    Jamendo's Pro tier — it is NOT enabled by setting a `client_id`.
    Users who need Pro licensing must obtain a separate Jamendo Pro
    subscription directly from Jamendo. VidiaForge does NOT claim Pro
    licensing is configured.
- **Preview/download permissions.** The preview URL comes from the
  track's `audio` field (streaming MP3); the download URL comes from
  `audiodownload`. Both are served by Jamendo's CDN.
- **Verification date.** 2025-10-10 (date this document was written).
- **Configuration requirements.** Set `AUDIO_PROVIDER=jamendo` and
  `JAMENDO_CLIENT_ID=<free client_id from
  https://developer.jamendo.com/admin/apps>`. The client_id is free;
  registering an app on Jamendo's developer portal returns one
  immediately. Without `JAMENDO_CLIENT_ID`, the provider reports
  `configured = false` and returns empty lists — the catalog endpoint
  honestly reports "Music source: jamendo (not configured)".
- **Status.** **IMPLEMENTED** — the adapter is in
  `src/lib/audio/jamendo-provider.ts`; contract tests pass
  (`tests/unit/audio-provider-contract.test.ts`, Jamendo license
  parsing, track-to-metadata conversion, and provider construction
  with + without `client_id`). **Live verification BLOCKED** in the
  repair sandbox (no `JAMENDO_CLIENT_ID` set AND no internet egress).
  The contract tests verify the parsing + validation logic against a
  recorded fixture; live API verification will be done once the
  deployment has a `JAMENDO_CLIENT_ID` and internet egress.

## 2. Built-in SFX — `BuiltinSfxProvider`

**V19.1 v5 — HONEST SFX LABELING.** All 8 built-in SFX are SYNTHETIC
— they are generated by FFmpeg from public-domain noise sources (white
noise, pink noise, brown noise) and pure tones (1 kHz, 1.2 kHz,
880 Hz). They are genuinely usable as production sound effects for UI
cues, transitions, and synthetic ambience beds — but they are NOT
field recordings.

Three of the eight entries were renamed in v5 because their previous
titles implied field recordings:

| Previous title (v3) | v5 title | Why renamed |
|---|---|---|
| "Camera Shutter" | "Synthetic Shutter" | A real "camera shutter" sound is a field recording of an actual camera shutter mechanism. The synthetic pink-noise burst is not that. |
| "Crowd Cheer" | "Synthetic Crowd Bed" | A real "crowd cheer" is a field recording of actual humans cheering. The synthetic white-noise bed is not that. |
| "Rain Ambience" | "Synthetic Rain Bed" | A real "rain ambience" is a field recording of actual rainfall. The synthetic brown-noise bed is not that. |

The other 5 entries keep their generic titles because a synthetic
whoosh / click / pop / notification / impact is still legitimately
that thing — the title does not imply a field recording. Every entry's
`description` field (internal — not exposed to end users via the
`AudioMetadata` surface) clearly states the noise type ("Synthetic
white-noise burst", "Synthetic 1 kHz short tone", etc.) so a developer
inspecting the catalog understands these are synthetic.

### 2.1 The 8 built-in SFX entries

- **Asset source.** 8 WAV files generated locally with FFmpeg from
  public-domain noise sources (white noise, pink noise, brown noise)
  and pure tones (1 kHz, 1.2 kHz, 880 Hz). Located at
  `public/audio/sfx-{1..8}-*.wav`. Defined in
  `src/lib/audio/builtin-sfx-provider.ts`.

  The 8 entries are:

  | ID | Title | Noise source | License |
  |---|---|---|---|
  | `sfx-whoosh` | Whoosh | Synthetic white-noise burst with fast attack/decay | CC0 |
  | `sfx-impact` | Impact Boom | Synthetic brown-noise rumble with low-frequency emphasis | CC0 |
  | `sfx-click` | Click | Synthetic 1 kHz short tone (UI click) | CC0 |
  | `sfx-pop` | Pop | Synthetic 1.2 kHz short tone (UI pop) | CC0 |
  | `sfx-shutter` | **Synthetic Shutter** (was "Camera Shutter") | Synthetic pink-noise burst — **NOT a real camera shutter** | CC0 |
  | `sfx-crowd` | **Synthetic Crowd Bed** (was "Crowd Cheer") | Synthetic white-noise bed — **NOT a real crowd recording** | CC0 |
  | `sfx-rain` | **Synthetic Rain Bed** (was "Rain Ambience") | Synthetic brown-noise bed — **NOT a real rain recording** | CC0 |
  | `sfx-notification` | Notification | Synthetic 880 Hz short tone (notification alert) | CC0 |

  The `artist` field is `"VidiaForge Library"` (not a fabricated artist
  name) and the `licenseType` field is `"CC0"` with
  `attributionRequired: false`.

- **License or usage terms.** **CC0** (public domain dedication). The
  source noise + pure tones are not themselves copyrightable, and the
  resulting WAVs are dedicated to the public domain via CC0. The CC0
  license is real and genuinely applies — these are not third-party
  recordings; they are synthetic waveforms generated from public-domain
  noise sources by FFmpeg on the build machine.
- **Attribution requirements.** **None** — CC0 does not require
  attribution.
- **Restrictions.** **None** — genuinely usable as production sound
  effects in monetized, derivative, commercial work. No share-alike
  obligation. No commercial-use restriction.
- **Preview/download permissions.** Same-origin URLs
  (`/audio/sfx-N-*.wav`) served directly from the VidiaForge origin.
  No CORS concerns; no third-party dependency at runtime.
- **Verification date.** 2025-10-10 (date this document was written).
- **Configuration requirements.** **None** — the built-in SFX are always
  available, regardless of `AUDIO_PROVIDER`. They ship with the
  application bundle.
- **Status.** **IMPLEMENTED** —
  `tests/unit/audio-catalog.test.ts` (10 tests) verifies every SFX
  has a real duration (read via FFprobe), a real file on disk, a CC0
  license, and no attribution required. All 10 tests pass. The
  provider reads the ACTUAL file metadata via FFprobe at startup so
  the durations reported to the frontend are never fabricated.

## 3. Template licensing — the 13 builtin templates

- **Asset source.** All 13 templates are builtin (defined in
  `src/lib/templates/builtin-templates.ts`). They contain **no embedded
  media** — only slot definitions. The user supplies the media (video,
  audio, images, text) that fills each slot. The templates themselves
  are layout + timeline + slot definitions, not pre-rendered video
  content.
- **License or usage terms.** All 13 templates are licensed `cc0`
  (public domain dedication) per their `license` object, which is
  defined uniformly as:
  ```
  license: { type: 'cc0', commercialUse: true, attributionRequired: false }
  ```
  Commercial use is explicitly allowed; attribution is not required.
  The `license.type` field is verified by the unit tests for every
  template.
- **Attribution requirements.** **None** — CC0 does not require
  attribution.
- **Restrictions.** **None** — the templates may be used commercially,
  modified, distributed, sublicensed, without obligation. The user's
  own media (placed into the slots) retains whatever license the user
  holds for that media — the template's CC0 license does not
  contaminate the user's media.
- **Preview/download permissions.** Template thumbnail PNGs are served
  from `/templates/{id}.png`. They are generated by
  `scripts/generate-template-thumbnails.ts` (see §4 for full details)
  and are LAYOUT PREVIEWS, not rendered-video previews. Each thumbnail
  is 6–14 KB (well under the 50 KB limit enforced by the test suite).
- **Verification date.** 2025-10-10 (date this document was written).
- **Configuration requirements.** **None** — the builtin templates are
  always available, regardless of `AUDIO_PROVIDER` or any other env var.
- **Status.** **IMPLEMENTED** — `tests/unit/template-integrity.test.ts`
  + `tests/unit/template-slot-validation.test.ts` verify:
  - Every template's `license` object is `{ type: 'cc0',
    commercialUse: true, attributionRequired: false }`.
  - Every clip references a real slot (no `placeholder-` assetId
    strings).
  - Every required slot has at least one referencing clip; every clip
    references an existing slot; no orphan slots.
  - Slot types match clip kinds (media slots accept video/image, audio
    slots accept audio, text/caption slots accept text, logo slots
    accept image).
  - Slot IDs, clip IDs, and track IDs are unique within each template.
  - Each template has a real `thumbnailUrl` whose PNG exists on disk
    and is under 50 KB.
  - The catalog covers 6 main categories (Social, Creator, Events,
    Business, Visual Styles, Lifestyle).
  - All template tests pass (688 `expect()` calls across the
    template test suite).

## 4. Template thumbnails — LAYOUT PREVIEWS, not rendered-video previews

**V19.1 v5 — HONEST TEMPLATE-THUMBNAIL LABELING.** This is a new
subsection (added in v5) that documents what the 13 template thumbnail
PNGs in `/public/templates/{id}.png` actually are. The previous (v3)
document described them briefly under §3's "Preview/download
permissions" bullet. In v5 they get their own section because the
honest-labeling update must explicitly say what they are NOT.

### 4.1 What the thumbnails are

- **Asset source.** The thumbnails are generated by
  `scripts/generate-template-thumbnails.ts`, which imports
  `BUILTIN_TEMPLATES` directly (the unified source of truth —
  `src/lib/templates/builtin-templates.ts`) and renders one
  representative PNG per template via FFmpeg's `lavfi` filter graph.
  This eliminates the "two independent implementations that can drift
  apart" anti-pattern called out in the V19.1 prompt — the thumbnail
  composition is derived from the template's ACTUAL structure.
- **Composition.** Each thumbnail is a single PNG composed of:
  1. A two-half gradient background (top half + bottom half) using the
     deterministic category color for the template's category (Social,
     Creator, Events, Business, Visual Styles, Lifestyle, Music). The
     background is a generated gradient — it is NOT a frame from a
     rendered video.
  2. The template's `title` rendered as drawtext at the top of the
     image (centered, uppercased, large font).
  3. The template's `category` rendered as drawtext immediately below
     the title (smaller font, lower opacity).
  4. **Media-slot rectangles**: up to 4 media clips (video/image/audio
     kind) are rendered as semi-transparent rectangles at their ACTUAL
     timeline positions. The timeline runs vertically
     (top-to-bottom = start-to-end), so a clip's Y position is derived
     from its `timelineStart / totalDuration` ratio. Each rectangle is
     labeled with its slot's `label` (the user-facing label, not the
     slot id).
  5. **Text-slot defaultValues**: up to 3 text clips are rendered as
     drawtext (using the clip's `text.text` field — typically the
     slot's `defaultValue`) at their timeline positions, with a
     semi-opaque background box so the text is legible against the
     gradient.
  6. The template's `aspectRatio` (e.g. `16:9`, `9:16`, `1:1`) rendered
     as drawtext in the bottom-left corner for orientation reference.
- **License.** **CC0** (public domain dedication). The thumbnails are
  generated from code (`scripts/generate-template-thumbnails.ts` +
  `BUILTIN_TEMPLATES`), not from licensed media. No third-party media
  appears in any thumbnail. The CC0 dedication applies because the
  composition is a code-generated derivative work of the template's
  structural metadata.
- **Attribution requirements.** **None** — CC0 does not require
  attribution.
- **Restrictions.** **None** — usable in commercial work without
  obligation.
- **Verification date.** 2025-10-10 (date this document was written).

### 4.2 HONEST LABEL — these are LAYOUT PREVIEWS, not rendered frames

**The thumbnails are LAYOUT PREVIEWS — illustrative compositions
showing the template's structural composition** (text positions, slot
positions, aspect ratio, title + category). **They are NOT frames from
real rendered exports.** A real rendered export would require sample
media to be supplied for every slot + a full render pipeline run; that
is out of scope for v5 (see §4.4).

The UI communicates this honestly:

- Each thumbnail's `<img>` element is rendered with
  `alt="${template.title} layout preview"` so screen-reader users and
  crawlers see the "layout preview" qualifier.
- The templates panel surfaces a visible "Layout" badge on each
  thumbnail so sighted users understand they are not seeing a
  finished-video preview.

### 4.3 Verification

- `tests/unit/template-integrity.test.ts` verifies that every template
  has a `thumbnailUrl` whose PNG file actually exists on disk under
  `/public/templates/{id}.png` AND is under 50 KB. This guarantees the
  thumbnails are real files (not missing-asset 404s) and small enough to
  load quickly in the catalog UI.
- The generator script (`scripts/generate-template-thumbnails.ts`) is
  deterministic given a fixed font + FFmpeg version, so re-running it
  produces byte-identical (or near-identical) PNGs. The thumbnails
  checked into `/public/templates/` were generated by running this
  script in the repair sandbox.
- `tests/unit/audio-catalog.test.ts` + the template test suite pass in
  the repair sandbox (no internet egress needed) — the thumbnails are
  fully verified.

### 4.4 Limitation — real animated previews are out of scope for v5

A real animated preview (a short MP4/WebP showing the template
animating with sample media in each slot) would require:

1. Sample media for every slot kind (sample video, sample image, sample
   audio, sample text) for every template — these would either need to
   be CC0-licensed stock or generated by FFmpeg.
2. A full render pipeline run per template (10–60 seconds each, × 13
   templates = 2–13 minutes of CPU time per regeneration).
3. Storage for 13 short videos (each a few hundred KB to a few MB)
   instead of 13 small PNGs (each 6–14 KB).
4. A UI surface that plays the video on hover/expand instead of showing
   a static image.

This is a meaningful future enhancement but it is out of scope for v5.
The static layout-preview thumbnails give the user a faithful visual of
the template's structural composition (text positions, slot positions,
aspect ratio) without the cost or complexity of a render pipeline run
for each catalog entry.

## 5. Important disclaimers

Read these carefully before relying on any audio or template asset.

### 5.1 License is verified at catalog-listing time, NOT at render time

The Internet Archive + Jamendo providers verify each item's license at
**catalog-listing time** — the moment `listMusic()` is called. They do
NOT re-verify the license at render time. If an item's license changes
between catalog-listing and rendering (for example, a contributor
re-licenses a track from CC-BY to CC-BY-NC, or removes it from the
catalog), the rendered output may carry a license the user did not
intend.

**What this means for the user:**
- The user should verify the license of each track they use by
  clicking the `licenseUrl` link surfaced in the UI (the attribution
  line embeds the original license URL).
- For commercial or monetized work, the user should re-check the
  license on the source platform (archive.org or jamendo.com) before
  publishing the rendered video.
- The 5-minute catalog cache (see §5.3) means a license change
  detected by the provider propagates to new catalog fetches within
  5 minutes; an item already added to the user's timeline is NOT
  re-checked.

VidiaForge does NOT warrant that the license reported at
catalog-listing time remains accurate for the lifetime of the user's
project.

### 5.2 Jamendo "Pro" license is NOT configured by this integration

Jamendo offers two licensing models:
1. **Creative Commons licenses** (CC-BY, CC-BY-SA, CC0) — free,
   available to anyone, suitable for many uses subject to the CC
   terms (attribution where required, no NC/ND uses, share-alike for
   CC-BY-SA).
2. **Jamendo Pro** — a paid subscription that grants broader rights
   (e.g. commercial use of NC tracks, no share-alike obligation for
   SA tracks, sync rights for advertising, etc.).

VidiaForge's Jamendo integration ONLY uses the CC license path. It
does NOT configure, authenticate, or proxy Jamendo Pro licensing.
Setting `JAMENDO_CLIENT_ID` enables CC-license catalog fetching only.
Users who need Pro licensing for a use case that exceeds the CC
terms must obtain a separate Jamendo Pro subscription directly from
Jamendo. VidiaForge does NOT claim Pro licensing is configured.

### 5.3 Timeout, caching, and rate-limit handling

The provider adapters enforce the following runtime guarantees:

- **10-second timeout per API call.** Every outbound HTTP request to
  the Internet Archive or Jamendo is aborted if it does not complete
  within 10 seconds. The provider returns an empty list on timeout
  rather than hanging the catalog endpoint.
- **5-minute catalog cache.** The provider caches the catalog response
  for 5 minutes. Within the cache window, repeated `listMusic()`
  calls return the cached list without re-hitting the upstream API.
  This is the behavior described in §5.1: license changes propagate to
  new catalog fetches within 5 minutes.
- **Rate-limit handling.** HTTP 429 responses from the upstream API
  cause the provider to return an empty list rather than retry-storm.
  The Internet Archive adapter additionally observes the Internet
  Archive's "no more than 1 request per second" policy by sleeping
  1 second between item-metadata fetches.
- **Server-side only.** All upstream API calls happen in the Node.js
  server runtime (`runtime = 'nodejs'`); the `JAMENDO_CLIENT_ID` is
  never exposed to the client bundle.

### 5.4 Live verification is BLOCKED in the repair sandbox

The repair sandbox used to prepare this production candidate does NOT
have internet egress. The contract tests
(`tests/unit/audio-provider-contract.test.ts`, 61 tests) verify the
parsing + validation logic against recorded fixtures
(`tests/fixtures/audio/api-responses/`). The fixtures include both
license-accept cases (CC-BY, CC-BY-SA, CC0, Public Domain) and
license-reject cases (CC-BY-NC, CC-BY-ND, no-license, unknown-license)
for both providers, so the license-filter logic is fully exercised.

What is NOT verified in the sandbox:
- A live call to `https://archive.org/advancedsearch.php`.
- A live call to `https://archive.org/metadata/{id}`.
- A live call to `https://api.jamendo.com/v3.0/tracks/`.
- End-to-end download + render of a real Internet Archive or Jamendo
  track through the render pipeline.

Live verification will be performed once the deployment has internet
egress (Internet Archive provider — no credentials required) and a
`JAMENDO_CLIENT_ID` is registered (Jamendo provider — free client_id
from https://developer.jamendo.com/admin/apps).

### 5.5 Built-in SFX + templates are fully verified

The built-in SFX and the 13 builtin templates do NOT depend on
internet egress or credentials. They are fully verified in the

- `tests/unit/audio-catalog.test.ts` (10 tests) — every SFX has a real

## 7. How a non-technical stakeholder should read this

- **Can I use the built-in SFX in a commercial video?** Yes — they are
  CC0, no attribution, no restrictions, fully verified. All 8 are
  synthetic (generated by FFmpeg from public-domain noise sources). In
  v5, the 3 entries whose previous titles implied field recordings
  have been renamed: "Camera Shutter" → "Synthetic Shutter", "Crowd
  Cheer" → "Synthetic Crowd Bed", "Rain Ambience" → "Synthetic Rain
  Bed". The other 5 keep generic titles (Whoosh, Impact Boom, Click,
  Pop, Notification) because a synthetic whoosh / click / pop /
  notification / impact is still legitimately that thing.

- **Can I use the built-in templates in a commercial video?** Yes —
  they are CC0, no attribution, no restrictions, fully verified. The
  user's own media (placed into the slots) retains its own license.

- **Are the template thumbnails frames from rendered videos?** No.
  The 13 template thumbnails in `/public/templates/{id}.png` are
  **LAYOUT PREVIEWS** — illustrative compositions generated by FFmpeg
  from the template's actual slot + clip structure (gradient
  background + title text + slot rectangles + text-slot defaultValues
  rendered at their real timeline positions). They are NOT frames
  from real rendered exports. The UI labels them with
  `alt="${template.title} layout preview"` and a visible "Layout"
  badge on the templates panel so users understand they are not
  seeing a finished-video preview. Real animated previews would
  require sample media + a full render pipeline run per template;
  that is out of scope for v5.

- **Can I use an Internet Archive track in a commercial video?** Yes,
  IF the track's license (shown in the UI) is CC-BY, CC-BY-SA, CC0, or
  Public Domain — the provider filters out the rest. For CC-BY and
  CC-BY-SA, you must include the attribution line (also shown in the
  UI) in your video description or end-card. For CC-BY-SA, the
  resulting video must carry the same CC-BY-SA license.

- **Can I use a Jamendo track in a commercial video?** Same answer as
  Internet Archive, PLUS: if your use case exceeds the CC terms (e.g.
  you want to use an NC track commercially, or you want to remove the
  share-alike obligation from an SA track), you must obtain a Jamendo
  Pro subscription directly from Jamendo. VidiaForge does NOT enable
  Pro licensing.

- **Are the Internet Archive + Jamendo licenses verified live?** No.
  Live API verification is BLOCKED in the repair sandbox. The contract
  tests verify the parsing + validation logic against recorded
  fixtures. Live verification will be done once the deployment has
  internet egress (and, for Jamendo, a registered `JAMENDO_CLIENT_ID`).
  The Internet Archive provider is now the default in `render.yaml`
  (v5) so the deployed music catalog is non-empty without
  credentials.

- **Is the license verified at render time?** No. The license is
  verified at catalog-listing time. If an item's license changes
  between catalog-listing and rendering, the rendered output may
  carry a license the user did not intend. Users should verify the
  license of each track they use by visiting the `licenseUrl` shown in
  the UI.
